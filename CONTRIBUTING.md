# Contributing to AgentVille

Thanks for wanting to help! AgentVille is a small, friendly project. Issues, ideas, art, translations and code are all welcome.

## Getting started

```bash
git clone https://github.com/arvabranch/AgentVille.git
cd AgentVille
npm install
AGENTVILLE_MOCK=1 npm run dev   # simulated agents: no API key, no spend
```

You need Node.js 20.19 or newer. Use npm (the repo ships a `package-lock.json`).

Before opening a pull request, make sure these pass:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

## Project layout

```
src/
├─ main/                 Electron main process (Node). The SDK and the API key live only here.
│  ├─ index.ts           App lifecycle, data loading, quit handling
│  ├─ window.ts          BrowserWindow (sandboxed, preload, CSP), dev screenshot capture
│  ├─ security.ts        Navigation/permission guards, safe external links
│  ├─ protocol.ts        app:// protocol for the packaged UI
│  ├─ ipc.ts             Typed ipcMain.handle wrapper (zod validation, trusted sender)
│  ├─ handlers.ts        Every IPC channel the UI can call
│  ├─ secrets.ts         API key storage with safeStorage
│  ├─ agents/            AgentManager, SdkSession (Agent SDK), MockSession, PermissionBroker…
│  ├─ chat/              ChatLog (history + streaming deltas), Markdown export
│  └─ store/             JSON persistence
├─ preload/index.ts      contextBridge → window.agentville (allow-listed channels only)
├─ shared/               IPC contract and types shared by every process
└─ renderer/             React UI + Phaser game
   └─ src/
      ├─ game/           Scenes, entities, world layout and code-generated art (art/)
      ├─ chat/           Chat panel, Markdown, permission and question cards
      ├─ ui/             HUD, dialogs, onboarding, settings
      ├─ state/          zustand store
      └─ i18n/           English and Spanish strings
```

### Adding an IPC channel

1. Declare it in `src/shared/ipc.ts` (`InvokeMap` or `EventMap`) and in the channel record below it. The compiler tells you if you forget.
2. Handle it in `src/main/handlers.ts` with `handle(channel, zodTupleSchema, handler)`. Validate every argument.
3. Call it from the renderer with `api.invoke(channel, ...args)`.

Never expose `ipcRenderer`, Node APIs or the API key to the renderer.

## Developer switches

These environment variables only work in development builds (they are ignored when the app is packaged):

| Variable | Effect |
| --- | --- |
| `AGENTVILLE_MOCK=1` | Simulated agents: streamed Markdown replies, tool rows, permission prompts (send a message containing "test") and questions (containing "question" or "pregunta"). No key needed. |
| `AGENTVILLE_DEMO=1` | Mock mode plus a seeded demo town in a throwaway data folder. Add `AGENTVILLE_MOCK=0` to use real agents in the demo town. |
| `AGENTVILLE_KEEP_DATA=1` | Keep the demo data between runs (to test persistence). |
| `AGENTVILLE_DEV_API_KEY=sk-ant-…` | Use this key without storing it (handy for testing the real SDK path). |
| `AGENTVILLE_LANG=es\|en` | Force the UI language. |
| `AGENTVILLE_DEBUG=1` | Verbose logs, including the agents' stderr (keys are always redacted). |
| `AGENTVILLE_CAPTURE=/path.png` | Save a screenshot of the window after `AGENTVILLE_CAPTURE_DELAY` ms (default 3500). Add `AGENTVILLE_CAPTURE_QUIT=1` to quit afterwards. |
| `AGENTVILLE_SCENARIO=office\|chat\|chat:<name>\|settings` | Demo scenarios for screenshots. |
| `AGENTVILLE_SCRIPT="left:780;key:E;type:hi;key:Return"` | Send real input events before the screenshot (see `src/main/devScript.ts`). |

Example: a smoke test that walks to an agent and opens its chat:

```bash
AGENTVILLE_DEMO=1 AGENTVILLE_SCENARIO=office AGENTVILLE_SCRIPT="left:780;key:E;wait:500" \
AGENTVILLE_CAPTURE=/tmp/agentville.png AGENTVILLE_CAPTURE_QUIT=1 npm run dev
```

Development builds keep their data in an `AgentVille-dev` folder (next to the normal app data folder), so they never touch a real install.

## Art and assets

- All art is generated by code at startup (`src/renderer/src/game/art/`): tiles from small procedural painters, characters from 16×24 string templates. Keep that style: 16 px tiles, the palette in `palette.ts`, a dark outline.
- If you add an external asset it must be your own work or released under CC0 (or a similarly permissive license), and you must record its source and license in [ASSETS.md](ASSETS.md).
- No characters, names or art from existing games, franchises or brands.

## Code style

- TypeScript everywhere, strict mode. Prefer small, typed modules.
- ESLint is the source of truth (`npm run lint`).
- UI strings go through `useT()` and live in both `src/renderer/src/i18n/es.ts` and `en.ts`.
- Keep the security model intact: context isolation, sandboxed renderer, validated IPC, no secrets in logs (use `log` from `src/main/log.ts`, which redacts keys).

## Commits and pull requests

- Use [Conventional Commits](https://www.conventionalcommits.org): `feat(world): …`, `fix(agents): …`, `docs: …`, `chore: …`.
- One topic per pull request. Describe what changed and how you tested it; add a screenshot for visual changes (the capture switches above make that easy).
- Make sure lint, typecheck, tests and build pass.

## Packaging

`npm run dist` builds installers with electron-builder on the current operating system. The Agent SDK installs the native Claude Code binary only for the platform you run `npm install` on, so build each platform on that platform (CI runners work well). macOS builds are ad-hoc signed by default; to ship signed and notarized builds, configure your identity in `electron-builder.yml`.

## Code of conduct

Be kind and assume good intent. Harassment or discrimination of any kind is not tolerated.
